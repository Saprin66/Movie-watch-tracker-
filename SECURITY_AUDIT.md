# Аудит безопасности Movie Grade

Дата: 17 октября 2026. Проверены сервер (Express 5, Prisma 5, PostgreSQL) и клиент (React 19, Vite 8).

Обозначения важности: 🔴 высокая, 🟠 средняя, 🟡 низкая, ⚪ к сведению.

**Проверка IDOR.** Просмотрены все маршруты с `:id`.

- Фильмы (`/api/movies/:id`, `/status`, `/review`, `/meta`) ищут запись по `id` и `userId: req.userId`, чужое изменить нельзя.
- Общие списки проверяют участие и роль создателя.
- Заявки в друзья принимаются только адресатом.
- Профиль `/api/users/:userId` и последний фильм `/last-watched` открыты всем вошедшим пользователям, так задумано и так описано в политике. Тексты отзывов видят только друзья.

## Этап 4. Бизнес-логика и ограничения частоты

| | Что нашлось | Что сделано |
|---|---|---|
| 🟡 | Лимиты стояли только на вход, регистрацию, коды и сброс пароля. Остальное API, включая поиск людей и заявки, можно было дёргать без ограничений. | Общий лимит 300 запросов в минуту с одного IP на все `/api`. Отдельные лимиты на вход и регистрацию остались. |
| 🟡 | Заявка в друзья несуществующему пользователю давала `500`, а на действие кроме accept/reject отвечала «ок». | `404` для несуществующих и неподтверждённых, `400` для неизвестного действия. |
| ⚪ | Повтор фильма: перед `create` есть `findFirst` по `userId + tmdbId + mediaType`. Самому себе заявку отправить нельзя, повторную тоже, в том числе уже подтверждённому другу. | Без изменений. |

Лимиты сделаны собственным модулем `middleware/rateLimit.js` (без `express-rate-limit`) и хранятся в памяти процесса: при перезапуске сервера счётчики сбрасываются, а при нескольких экземплярах считаются отдельно. `trust proxy` включён, чтобы за прокси хостинга лимит считался по IP посетителя.

## Рекомендации

1. **На хостинге сервера** задать `NODE_ENV=production` и `CORS_ORIGINS` со всеми адресами, откуда открывается сайт, через запятую (например, адрес Cloudflare Workers, если он используется). Иначе запросы с этого адреса будут отклонены.
2. **Зависимости** регулярно проверять: `cd server && npm audit` и `cd client && npm audit`, исправления через `npm audit fix` (без `--force`, после него проверить сборку). Включить Dependabot в настройках репозитория GitHub (Security → Dependabot alerts / security updates).
3. **Ключ TMDB** ограничить в настройках аккаунта TMDB и при утечке перевыпустить. `JWT_SECRET` держать длинным (32+ случайных символа) и менять при подозрении на утечку: все сессии сбросятся.
4. **Фронтенд**: добавить заголовки (`Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy`) в настройках Vercel (`vercel.json → headers`). CSP нужно составлять под реальные домены: API, TMDB, Google Fonts, jsDelivr, YouTube.
5. **Токен** хранится в `localStorage`, поэтому любая XSS стала бы угоном сессии. React это закрывает, пока нигде не появится `dangerouslySetInnerHTML` и вставка пользовательских ссылок в `href`. Держать это правило в код-ревью.
6. **Мониторинг**: смотреть логи сервера на всплески `401`, `403`, `429` и `CORS: запрос с неразрешённого адреса`. Подключить сбор ошибок (например, Sentry) и бэкапы PostgreSQL у хостинга базы.
7. **Перенос лимитов в Redis**, если сервер будет запущен в нескольких экземплярах.
